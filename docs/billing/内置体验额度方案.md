# 内置体验额度方案与统计标准

> 目标：① 给出对用户合适的**每月内置体验额度**建议；② 落地一套**通用额度统计标准**
> （按 token 计量、输入/输出分开计权、只记录内置额度消耗、自定义 BYOK 不记账），
> 并**预留后续接入收费大模型**的计价能力。

---

## 1. 背景与现状

### 1.1 额度模式现状

| 项 | 现状 |
| --- | --- |
| 模式常量 | `config.rs:110-111`：`QUOTA_MODE_EMBEDDED = 1`（内置额度）、`QUOTA_MODE_BYOK = 2`（自带 Key） |
| 落库 | `app_settings` 表 `type=1` 行的 `is_custom_quota_used` 列（1=内置额度 / 2=自带 Key） |
| 读写 | `db/repositories/app_settings.rs:42-59` |
| 命令 | `commands/settings.rs:69-111`（`settings_set_quota_mode`，带 BYOK 前置校验） |

### 1.2 现有缺口（调研结论）

1. **无任何用量记录设施**：DB 全部 9 个对象为
   `messages` / `summaries` / `facts` / `pet_states` / `affection_logs` / `app_settings` /
   `vec_memory`(vec0) / `custom_model_settings` / `default_model_settings`，
   **不存在 usage / quota / billing / stats 表**。
2. **`messages.tokens` 是死列**：建表 SQL 有该列（默认 0），但插入语句未包含它，故恒为 0，
   不能作为统计依据。
3. **响应不带 token 用量**：`llm/client.rs` 请求体只有 `model / messages / stream`；
   SSE 结构体 `SseFrame/SseChoice/SseDelta` 无 `usage` 字段；
   且 `next_sse_delta` 对 usage 帧「主动忽略」。
   → **当前无法获得真实用量**，必须先打通上报。
4. **三个消费点各自独立读额度模式并组链**：
   `commands/chat.rs:75-182`、`commands/probe.rs:81-86`、`llm/diary.rs:177-185`。
   → 若各写一遍记账，口径必然漂移；**必须收敛成单点**。
5. **`builtin_state` 仅进程内存**（`llm/router.rs:129-143`），不做持久化。
6. **口径不一致（需在方案中统一）**：所谓「内置额度」目前实际是
   `M6__default_models.sql` 里的**明文种子 Key 直连厂商**（智谱 / 硅基流动）；
   而 `EMBEDDED_QUOTA_BASE_URL`（qiqi-quota Workers 端点）**只用于 embedding**。

## 2. 月度额度建议

### 2.1 同类应用对照

| 类型 | 代表 | 常见免费策略 | 对本项目的借鉴 |
| --- | --- | --- | --- |
| AI 伴侣 / 角色扮演 | Character.AI、Talkie、星野 | 不限量但**限速 / 排队**，高峰期降级到小模型 | 用「额度 + 降级」而非直接断供 |
| 厂商官方助手 | 豆包、元宝、Kimi、DeepSeek App | 官方补贴，近乎不限量 | **不可照搬**——补贴成本在厂商侧，第三方客户端无此条件 |
| 第三方客户端 / 插件 | ChatBox、Cherry Studio、沉浸式翻译、Bob | 主流为 **BYOK**；内置额度多为「一次性试用字符数」或「月度点数」，量级几万~几十万 token | 明确定位：**内置额度=体验，重度使用转 BYOK** |

### 2.2 推荐档位（已确认：日常陪伴档）

| 项 | 建议值 | 说明 |
| --- | --- | --- |
| 月度总额度 | **200,000 credits**（≈100 轮） | 覆盖轻度日常陪伴 |
| 日均折算 | ≈3.3 轮/天 | 早晚问候 + 偶尔闲聊够用 |
| 单日上限 | **15 轮/天** | 防月初一次性刷完 |
| 单条输入上限 | **4,000 字** | 防单轮超长上下文吃满额度 |
| 新用户首月 | +50 轮（可选） | 降低尝鲜门槛 |

### 2.3 折算依据（token 估算口径）

单轮（一问一答）典型构成：

| 组成 | 估算 |
| --- | --- |
| System Prompt（人设 + 关系等级指令 + 宠物名） | ≈400 token |
| 会话摘要头（命中后） | ≈150 token |
| 最近上下文（≤ MAX_CONTEXT_MESSAGES=12 条） | ≈800~1,500 token |
| 记忆检索注入（facts + 向量近因） | ≈300 token |
| 本轮用户输入 | ≈30~80 token |
| 助手输出 | ≈60~150 token |

→ 单轮 ≈1,800 credits（按 `W_in=1.0 / W_out=2.0` 计），**100 轮 ≈ 200,000 credits**。

### 2.4 防滥用

- 单日 15 轮上限：平滑消耗，避免月初透支后整月不可用；
- 单条输入 4,000 字上限：超长上下文按截断后长度计费；
- **失败不扣点**：超时 / 熔断 / 解析失败不扣额度（避免"没用上还掉额度"）；
- **BYOK 完全不记账**：命中自定义段不写库、不展示，天然满足隐私与成本分离。

## 3. 通用额度统计标准

### 3.1 计量单位：credits（额度点）

- 定义：**1 credit = 1 个基准模型等价 token**；
- 基准：`default_model_settings` 的主对话内置模型；
- 理由：后续接入收费大模型时，不同模型单价差异大；用统一点数只需调整权重表，统计与展示逻辑零改动；
- 纪律：与项目既有约定一致——**不写死价格**，只维护相对权重。

### 3.2 单次请求扣减公式

```
credits = ceil(prompt_tokens × W_in(model) + completion_tokens × W_out(model))
```

- 默认权重：`W_in = 1.0`，`W_out = 2.0`（多数厂商输出单价约为输入的 2~4 倍，取 2 为保守可解释值）；
- `ceil` 保证「用了就算 1 点」，避免 0 扣减导致的免费用漏洞；
- 权重表集中在 `config.rs`，后续按模型/档位扩展。

### 3.3 token 来源优先级

1. **接口返回的 `usage`**（优先，精确）；
2. 缺失（流式未携带 / 代理不返回）→ **端侧估算**：`ceil(chars / 1.6)`（中文为主）；
3. 记录中标注 `tokenSource = "api" | "estimated"`，便于后续对账与修正。

### 3.4 记账范围（关键）

- **仅统计内置额度**：命中链段 `tier == "builtin"` 才落明细；
- **自定义 BYOK（`tier == "custom"`）不落库、不展示**——用户自带 Key 的消耗与内置额度无关；
- 后台任务（蒸馏 / 摘要 / 日记）同样记账并标注 `scene`，便于核算真实成本。

### 3.5 扣减时机

- **成功后记账**（流式以收尾帧为准）；
- 失败 / 超时 / 熔断：**不扣点**，但记一条 `ok=false` + `error` 明细，用于排查与审计；
- failover：每次**真实发起的 LLM 请求**各记一条（失败不扣点），最终成功那次扣点；
- 网络层自动重试：只按**最终一次**记账，避免重试放大扣费。

### 3.6 周期与重置

- 本地时区**自然月**，周期键 `period_key = YYYY-MM`；
- 每月 1 日 00:00（本地时间）重置已用计数；
- **不结转**：未用完额度不累积到下月；
- 跨月归属以**请求发生时间**为准。

> ⚠️ 时间戳陷阱：`created_at` 默认值为 **UTC**。按本地日期过滤/汇总必须做本地时间转换
> （既有回归说明，沿用 `date(created_at,'localtime')` 一类写法，勿直接比较 UTC）。

### 3.7 计价扩展预留（后续收费大模型）

- credits 与真实货币解耦：模型权重表只表达**相对成本**，不写死价格；
- 后续接入收费模型 = 在权重表新增条目，统计/展示/限额逻辑**零改动**；
- 本次**不实现**计费与支付，仅预留计价接口与数据字段。

## 4. 数据模型（草案）

新增迁移 `M8__quota_usage.sql`（**追加到链尾，禁止改动 M1~M7**），`TARGET_VERSION` 升为 `8`。
表风格照抄 `affection_logs`。

```sql
CREATE TABLE IF NOT EXISTS quota_usage (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    period_key    TEXT    NOT NULL,          -- 本地自然月 YYYY-MM
    scene         TEXT    NOT NULL,          -- chat / proactive / distill / diary
    tier          TEXT    NOT NULL,          -- builtin（记账）/ custom（不落库）
    model         TEXT    NOT NULL,
    prompt_tokens INTEGER NOT NULL DEFAULT 0,
    completion_tokens INTEGER NOT NULL DEFAULT 0,
    total_tokens  INTEGER NOT NULL DEFAULT 0,
    credits       INTEGER NOT NULL DEFAULT 0, -- 计权后扣减点数
    ok            INTEGER NOT NULL DEFAULT 1, -- 1 成功 / 0 失败
    error         TEXT                        -- 失败原因（成功为空）
);

CREATE INDEX IF NOT EXISTS idx_quota_usage_period ON quota_usage (period_key, created_at DESC);
```

**月度汇总缓存**：`quota_usage_monthly (period_key PRIMARY KEY, granted, used, requests, updated_at)`，
与明细写入**同一事务**内增量 upsert，UI 读取免全表 SUM。

## 6. 前端展示口径

- **默认汇总展示**：已用点数 / 总量、剩余百分比、进度条（接近上限转警示色，耗尽转耗尽色）、本月请求次数、周期与重置时间；
- **明细按需展开**：抽屉按时间倒序列出每次请求（时间、场景、模型、输入 token、输出 token、扣减点数、状态与失败原因）；
- **降级提示**：额度耗尽时卡片顶部出现提示条，说明已切轻量模型与恢复方式（情绪化短句，**不播报数值**——遵守 C5/C7 红线）；
- **BYOK 不展示**：自定义使用额度不记录、不展示。
