## 一、设计原则

1. **分层与栈一致**：目录树是架构图的物理投影——Tauri 双进程（Rust 系统层 / WebView 表现层）对应两个顶层目录 `src-tauri/` 与 `src/`，二者仅经 IPC（`#[tauri::command]` ↔ `src/api/`）通信。
2. **依赖单向**：`views → components → composables → (api | renderer | state) → utils`；Rust 侧 `commands → 领域模块(db/llm/affection/proactive/probe/window) → 基础设施(error/config)`。禁止反向引用与跨层跳跃。
3. **真源唯一**：每类知识只有一个家（设计 token → `tokens.css`；服务商预设与常量 → Rust `config.rs`；IPC 类型 → `src/api/types.ts`；schema 版本 → `PRAGMA user_version`）。发现同一值有两处，先按 `CODEBUDDY.md`「Configuration Management」表裁决。
4. **业务与基建分离**：`components/ui`、`utils`、Rust `error/config` 不含任何业务语义；业务组件/领域模块不反向污染基建。
5. **可测试优先**：纯逻辑（物理算法、好感度、微随机、Prompt 拼装）独立成无副作用模块，天然可单测（rule.md「隔离测试」）。
6. **演进不做手术**：新能力以"新增目录/文件 + 注册"接入（§8 扩展路径），不允许为塞新功能而打破既有边界。

### 3.1 前端职责边界（红线）

| 目录 | 允许 | 禁止 |
| :--- | :--- | :--- |
| `api/` | `invoke`、事件监听封装、DTO 类型 | 业务逻辑、DOM/PIXI 操作 |
| `renderer/` | PIXI、`physics.ts` 纯算法 | import Vue / `api/` / `state/`（输入一律由 `mount` 参数与显式方法传入） |
| `composables/` | 生命周期、实例持有、事件订阅 | 持久业务规则（算法放 `renderer/physics.ts` 或 `utils/`） |
| `state/` | reactive 数据与简单派生 | 副作用（invoke/定时器——留给 composables） |
| `components/ui/` | 通用交互 | **import `api/`、业务常量、业务 store**（纯 props/emit） |
| `components/{pet,settings,affection,memory}/` | 业务组合 | 跨域引用（affection 组件不得 import memory 组件；共用下沉 ui/） |
| `views/` | 组装、面板路由 | 业务算法 |
| `utils/` / `constants/` | 纯函数/常量 | import Vue/PIXI/api |

### 4.1 Rust 职责边界（红线）

| 模块 | 允许 | 禁止 |
| :--- | :--- | :--- |
| `commands/` | 参数校验、调用领域模块、组装返回 DTO | 业务规则、直连 DB/HTTP |
| `db/repositories/` | 参数化 SQL、行映射 | 业务决策、`emit` 事件、拼接 SQL 字符串 |
| `llm/` | 网络请求、流解析、Prompt 拼装 | 直接写库（沉淀落库经 `db/repositories`；编排写在 `distill.rs`） |
| `probe/` | Win32 读取、事件广播 | 修改窗口属性（属 `window/`）、读屏幕内容 |
| `window/` | 窗口属性操作 | 直接轮询 Win32（统一经 `probe/` 单点数据源） |
| `affection/`、`proactive/` | 纯规则计算 | I/O（连接、请求、文件）——由调用方注入数据 |
| `config.rs` | 常量定义 | 任何运行时可变状态（那属于 `state.rs` 或 DB） |

**探针单点原则**：`GetCursorPos` 只在 `probe/cursor.rs` 轮询一次（约 100ms，事件驱动），`window/click_through.rs` 与前端 `lookAt` 都消费同一事件——这是 CPU < 2% 红线的关键实现约束。

## 五、命名规范

| 对象 | 规则 | 示例 |
| :--- | :--- | :--- |
| Rust 模块/文件 | `snake_case` | `click_through.rs`、`pet_states.rs` |
| Rust 类型/枚举 | `PascalCase` | `AppError`、`PetStateRow` |
| Rust 函数/变量 | `snake_case` | `settle_decay()` |
| Rust 常量 | `SCREAMING_SNAKE_CASE` | `EMBEDDING_DIM`、`PROBE_INTERVAL_MS` |
| Vue 组件文件 | `PascalCase.vue`，与组件名一致 | `SpeechBubble.vue` |
| TS 文件 | **与主导出同名**：类型/类 → `PascalCase.ts`；函数工具/store → `camelCase.ts` | `IPetRenderer.ts`、`useChatStream.ts`、`timeWindow.ts` |
| 事件名（IPC emit） | `pet:<域>:<动作>`，全小写 | `probe:cursor:move`、`chat:stream:delta`、`affection:changed` |
| Tauri 命令 | `<域>_<动作>` snake_case | `settings_get_typed`、`chat_send_stream` |
| 测试文件 | 前端 `*.spec.ts`；Rust 内联 `#[cfg(test)]` + `src-tauri/tests/` 集成 | `decay.spec.ts`、`migrations_it.rs` |
| 设计文档 | 中文描述名或 kebab-case，标题带版本号 | `窗口B-设置界面设计方案.md` |
| CSS | token 用 `--域-语义`（`--matcha` 保留历史名），BEM 变体于组件内 scoped | — |

## 七、依赖方向总览

```
前端：views ──▶ components ──▶ composables ──▶ ┌─ api/ ────────▶ (IPC) ──▶ commands/
                                 │             └─ renderer/                │
                                 └─ state/                                  ▼
IPC 事件 ◀────────────────────────────────────────────────────── probe/ · llm/(SSE emit)
Rust：commands ──▶ 领域模块(affection/proactive/llm/window) ──▶ db/repositories ──▶ SQLite
                          │                                        ▲
                          └──────────── config.rs（常量）◀─────────┘
```

- 任何 `import` 出现环 → 视为设计错误，先拆接口再写代码。
- 前端除 `api/` 外出现 `invoke` 字样即违规；Rust 除 `commands/` 出现 `#[tauri::command]` 即违规。
