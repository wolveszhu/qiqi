# 桌面数字生命（PC 桌宠）技术开发文档 v2.0
## 一、 项目概述
+ **产品定位**：住在你桌面上的数字生命。有性格、有记忆、有主动性，偶尔帮你干活，大部分时间陪着你。
+ **核心卖点**：你电脑里唯一会主动找你说话的东西。
+ **目标平台**：Windows 10 及以上 (x64)。
+ **开发模式**：单人全栈开发（重度依赖 AI 辅助编程，采用 AI 结对编程模式，极简架构，快速验证 MVP）。
+ **MVP 形态**：双窗口模式（<font style="color:rgb(15, 17, 21);">局部窗口模式（不使用全屏 Overlay）	</font> + 常规设置窗口）。形象使用纯代码绘制的极简猫咪/狗子，不依赖美术资源。

---

## 二、 核心技术栈选型
| 模块 | 技术选型 | 选型理由 |
| :--- | :--- | :--- |
| **桌面框架** | **Tauri 2** (Rust + WebView2) | 内存占用极低，原生多窗口支持极佳，打包体积小。 |
| **系统层语言** | **Rust** | 负责透明窗口、动态点击穿透、Win32 全局状态轮询、文件系统。 |
| **表现层语言** | **TypeScript + React/Vue** | 负责 UI 设置面板、气泡流式文本展示。 |
| **渲染引擎** | **PIXI.js (Graphics 绘制)** | MVP 阶段纯代码绘制，无需美术资产，依靠物理算法实现“果冻感”。 |
| **本地数据库** | **SQLite + SQLCipher + sqlite-vec** | 单文件零配置，支持全库 AES 加密，支持本地向量检索。 |
| **AI 对话** | **OpenAI 兼容流式接口 (SSE)** | 用户自备 API Key<font style="color:rgb(15, 17, 21);">或使用内置体验额度。</font>前端不接触明文，由 Rust 侧直接发起请求。 |
| **TTS 引擎** | **Edge TTS** (初期) | 免费、极低延迟、无需本地部署模型。 |

## 三、 窗口与系统架构
采用 **“系统外壳 (Rust) + 表现前端 (WebView)”** 的分层架构；**<font style="color:rgb(15, 17, 21);">“1 个局部透明桌宠窗口 + 1 个常规设置窗口”</font>**<font style="color:rgb(15, 17, 21);"> 的架构。放弃全屏覆盖，最大化节省系统性能并兼容全屏游戏。</font>

### 3.1 双窗口模式
+ **窗口 A (****<font style="color:rgb(15, 17, 21);">局部桌宠层</font>****)**：<font style="color:rgb(15, 17, 21);">固定大小（如 </font>`<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">400x400</font>`<font style="color:rgb(15, 17, 21);"> 逻辑像素）</font>、无边框、全透明背景、置顶、不显示在任务栏。只负责渲染 PIXI 角色和对话气泡。
+ **窗口 B (Settings 设置层)**：常规窗口，带实体背景。承载 API 配置、勿扰时段、好感度查看、自定义形象导入。关闭时仅隐藏（`hide`），不销毁。

### <font style="color:rgb(15, 17, 21);">3.2 拖拽与移动机制（Rust 接管）</font>
+ **<font style="color:rgb(15, 17, 21);">禁止前端直接拖拽 PIXI 精灵</font>**<font style="color:rgb(15, 17, 21);">。</font>
+ **<font style="color:rgb(15, 17, 21);">拖拽物理形变</font>**<font style="color:rgb(15, 17, 21);">：当用户按住猫咪拖拽时，计算鼠标在窗口内的相对偏移量，反馈给 PIXI 渲染层。利用弹簧物理公式（弹簧阻尼系统），让猫咪身体产生夸张的“拉伸（拉面条）”效果，松手后产生剧烈的 Q 弹恢复动画。</font>
+ **<font style="color:rgb(15, 17, 21);">正确流程</font>**<font style="color:rgb(15, 17, 21);">：前端监听猫咪的 </font>`<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">pointerdown</font>`<font style="color:rgb(15, 17, 21);"> 事件 -> 触发 IPC 通知 Rust -> Rust 侧调用 </font>`<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">window.start_dragging()</font>`<font style="color:rgb(15, 17, 21);">。由操作系统原生接管窗口拖动，确保 60fps 丝滑跨屏移动。</font>
+ **<font style="color:rgb(15, 17, 21);">坐标跟随</font>**<font style="color:rgb(15, 17, 21);">：窗口移动后，Rust 侧更新全局坐标，前端 PIXI 重新校准猫咪在窗口内的相对位置。</font>

### 3.3 动态点击穿透 (Click-Through)
1. <font style="color:rgb(15, 17, 21);">窗口初始为全透明穿透状态。</font>
2. 前端 PIXI 计算角色的真实包围盒（Hit Region），通过 IPC 上报给 Rust。
3. Rust 后台轮询全局鼠标坐标（Win32 `GetCursorPos`），<font style="color:rgb(15, 17, 21);">判断是否在猫咪身上</font>。
4. **<font style="color:rgb(15, 17, 21);">在猫咪身上</font>**：设置 `set_ignore_cursor_events(false)`，拦截点击（触发果冻形变）。
5. **在****<font style="color:rgb(15, 17, 21);">透明区域</font>**：设置 `set_ignore_cursor_events(true)`，鼠标事件穿透到底层桌面/浏览器。

### 3.4 全局状态探针 (Rust 侧)
+ **视线跟随**：获取全局鼠标坐标传给前端，驱动 `IPetRenderer.lookAt(x, y)`。
+ **空闲检测**：使用 `GetLastInputInfo`，持续 N 分钟无输入，通知前端触发睡觉/打哈欠动画。
+ **<font style="color:rgb(15, 17, 21);">告别准点打卡</font>**<font style="color:rgb(15, 17, 21);">：Rust 侧不采用绝对时间（如 09:00）触发，而是设立时间窗口（08:30 - 09:30）。</font>
+ **<font style="color:rgb(15, 17, 21);">情境感知</font>**<font style="color:rgb(15, 17, 21);">：Rust 通过 Win32 API 获取当前活跃窗口的进程名（仅获取进程名，不涉及屏幕内容），传给前端。如果检测到用户在 </font>`<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">Code.exe</font>`<font style="color:rgb(15, 17, 21);"> (VSCode) 或打游戏，则取消当次的“微随机”主动互动，避免打扰。</font>

### <font style="color:rgb(15, 17, 21);">3.5 气泡防截断与跟随</font>
+ <font style="color:rgb(15, 17, 21);">气泡 UI 由 React 渲染，限制在窗口 A 内。</font>
+ <font style="color:rgb(15, 17, 21);">前端动态计算气泡的渲染方向。若猫咪靠近窗口右边缘，气泡向左偏移弹出，防止被 OS 窗口边界裁切。</font>

### <font style="color:rgb(15, 17, 21);">3.6 一键物理交互（新增）</font>
+ **<font style="color:rgb(15, 17, 21);">静音/勿扰小黑屋</font>**<font style="color:rgb(15, 17, 21);">：在桌宠窗口内提供一个隐蔽的快捷交互区域（例如在猫咪头顶渲染一个小铃铛，点击后铃铛打叉，进入勿扰模式）。或者，允许用户将猫咪拖拽到屏幕边缘，触发“边缘吸附”并进入休眠/静音状态，彻底停止主动语音和弹窗。</font>

## 四、 核心功能模块与开发流程
### 模块 1：形象渲染与物理交互（MVP）
**【功能介绍】**  
第一版不使用美术资源，采用 PIXI.js 纯代码绘制一只极简猫咪/狗子。赋予其“果冻物理”与“视线跟随”效果，让基础几何图形拥有生命力。

**【开发流程】**

1. **定义接口**：在 TypeScript 侧定义 `IPetRenderer` 接口（包含 `mount`, `playAction`, `setExpression`, `lookAt`, `getHitRegion`, `dispose`）。
2. **代码绘制**：实现 `CodeCatRenderer`，使用 `PIXI.Graphics` 绘制身体、耳朵、摇晃的尾巴和眼睛容器。
3. **物理动画**：在 PIXI 的 `Ticker` 中，利用 `Math.sin` 驱动待机呼吸；利用阻尼公式（`val += (target - val) * 0.1`）实现点击瞬间的 `scaleX/scaleY` 果冻形变。
4. **视线跟随**：接收 Rust 传来的全局鼠标坐标，限制眼睛容器的偏移量（3-5像素），实现盯着用户看。

---

### 模块 2：桌面融合与系统交互（MVP）
**【功能介绍】**  
确保桌宠“住”在桌面上，不挡视线、不烦人，能随时移动和隐藏。

**【开发流程】**

1. **局部透明穿透**：配置 Tauri 窗口 A（透明、无边框、置顶）。前端上报角色的包围盒（Hit Region）给 Rust，Rust 轮询鼠标坐标，动态切换 `set_ignore_cursor_events` 实现“点到猫有反应，点到旁边穿透到桌面”。
2. **丝滑拖拽**：禁止前端拖拽 PIXI 精灵，监听 `pointerdown` 后通知 Rust 调用 `window.start_dragging()`，由系统接管窗口移动。
3. **系统托盘与自启**：使用 Tauri 原生插件配置托盘菜单（显示/隐藏、设置、退出）和开机自启。
4. **全局快捷键**：注册 `Ctrl+Shift+P` 唤起输入框，`Ctrl+Shift+H` 隐藏桌宠。

### 模块 3：双窗口与设置面板（MVP）
**【功能介绍】**  
窗口 B 负责承载所有配置，核心包括：大模型配置、勿扰时段、好感度看板、形象管理。

**【开发流程】**

1. **安全存储 API**：设置面板输入 API Key -> 通过 IPC 发给 Rust -> 存入 SQLCipher 加密的 `app_settings` 表，前端绝不存明文。
2. **勿扰与主动频率**：在设置面板配置勿扰时段（如 `09:00-18:00`）和主动频率（安静/正常/粘人）。
3. **好感度看板**：读取 `pet_states` 渲染进度条与等级，读取 `affection_logs` 渲染近期变动流水。

### 模块 4：AI对话与多维记忆系统（MVP核心）
**【功能介绍】**  
结合长期记忆，越相处越了解你。对话不是“你问我答”，而是允许废话、跑题的陪伴感聊天。

**【开发流程】**

1. **记忆检索**：用户输入 -> 去 `vec_memory` (向量) 和 `facts` (事实) 做混合检索 -> 拼装 System Prompt。
2. **流式输出**：Rust 代理请求 LLM (SSE)，前端 React 气泡以打字机效果渲染文字，同时驱动 PIXI 切换表情。
3. **异步沉淀**：对话结束后，触发后台任务，让廉价 LLM 提取对话中的新事实和摘要 -> 写入 `facts` 表和 `vec_memory` 表。
4. **触发机制**：支持文本输入、文件/图片拖入（Rust 处理文件路径传给前端多模态模型）。

---

### 模块 5：好感度与关系进化引擎（MVP）
**【功能介绍】**  
好感度（0-1000分）决定关系等级（陌生->熟人->亲密->羁绊），关系等级直接影响 LLM 的说话语气。

**【开发流程】**

1. **正向反馈**：启动打卡 (+10)、抚摸交互 (+1，日上限20)、深度对话 (+5)。
2. **弹性衰减**：应用启动时对比 `last_decay_at`。超过 3 天未互动每天 -5，**但降至当前等级下限即停止**，防止用户产生挫败感。
3. **禁忌判定**：对话后的异步沉淀环节，让 LLM 评估是否触犯禁忌，扣除 10-30 分。
4. **关系注入**：每次对话生成时，读取当前 `relationship_level`，拼接到 Prompt 中（如：Lv.3 亲密，表现为会撒娇、会表达想念）。

## 五、 渲染系统设计
使用 PIXI.js 纯代码绘制，利用数学公式赋予“生命力”。

### 4.1 形象拆解（极简猫咪/狗子）
+ **身体**：圆角矩形或椭圆（如绿色/黄色）。
+ **面部**：白色大椭圆，叠加小椭圆作为刘海。
+ **耳朵**：两个三角形。
+ **尾巴**：利用 Bezier 曲线绘制，在 `Ticker` 中用正弦函数左右摇摆。
+ **眼睛**：两个独立的黑色胶囊形状，放在单独的 `Container` 中。

### 4.2 核心动画算法（果冻物理）
不使用帧动画，纯靠代码控制 `scaleX` 和 `scaleY`：

```typescript
// 点击事件触发瞬间拉宽压扁，随后每帧阻尼回弹
function onPetClick() {
    scaleX = 1.15; // 瞬间压扁
    scaleY = 0.85;
}
app.ticker.add((delta) => {
    // 1. 待机呼吸：利用正弦波
    const breath = Math.sin(time) * 0.03;
    pet.scale.x = scaleX - breath * 0.5;
    pet.scale.y = scaleY + breath;

    // 2. 阻尼回弹恢复
    scaleX += (1 - scaleX) * 0.1;
    scaleY += (1 - scaleY) * 0.1;
});
```

拖拽形变算法 (Stretch & Squash)

```typescript
// 伪代码：拖拽时基于鼠标偏移计算拉伸
function onDrag(deltaX, deltaY) {
    // 拉伸强度与鼠标移动速度/距离正相关
    const stretchFactor = Math.min(Math.sqrt(deltaX**2 + deltaY**2) * 0.01, 1.5);
    
    // 根据拖拽方向修改 scaleX/scaleY
    pet.scale.x = 1 + stretchFactor;
    pet.scale.y = 1 - stretchFactor * 0.5; 
    // 松手时，利用原有的阻尼公式弹回 1, 1
}
```

### 4.3 面向接口编程 (`IPetRenderer`)
为后续支持用户自定义图片/动图/Live2D，必须定义统一接口：

```typescript
interface IPetRenderer {
  mount(container: PIXI.Container): void;
  playAction(actionName: string): void;   // 如 'idle', 'click', 'sleep'
  setExpression(expressionName: string): void; // 如 'happy', 'angry'
  lookAt(x: number, y: number): void;     // 视线跟随
  getHitRegion(): { x: number, y: number, width: number, height: number };
  dispose(): void;                        // 释放资源
}
```

目前的 `CodeCatRenderer` 和未来的 `CustomSpriteRenderer` 均需实现此接口。表情实现仅通过改变眼睛容器的 `scale.y`（如变成横线代表犯困，变成弯弧代表开心）。

## 六、 数据库与记忆管道设计
### 5.1 数据库表结构（6 张核心表）
使用 SQLCipher 进行全库加密，密钥由系统凭据管理器保存。

1. `messages`**（对话记录）**：
    1. id	BIGINTEGER	PRIMARY KEY AUTOINCREMENT	消息唯一ID
    2. session_id	VARCHAR(50)	NOT NULL	会话ID（用于划分不同时间段的聊天）
    3. role	TINYINT	NOT NULL	消息角色，默认0user，1assistant（'user' 或 'assistant'）
    4. content	TEXT	NOT NULL	消息文本内容
    5. tokens	INTEGER	DEFAULT 0	该条消息消耗的Token数（用于统计）
    6. created_at	TIMESTAMP	DEFAULT CURRENT_TIMESTAMP	消息发生时间
    7. updated_at	TIMESTAMP	DEFAULT CURRENT_TIMESTAMP	消息更新时间
2. `summaries`**（会话摘要）**：对话过长时由 LLM 异步生成。
    1. id	INTEGER	PRIMARY KEY AUTOINCREMENT	摘要唯一ID
    2. session_id	VARCHAR(50)	UNIQUE, NOT NULL	对应的会话ID
    3. summary_text	TEXT	NOT NULL	大模型生成的摘要内容
    4. created_at	TIMESTAMP    DEFAULT CURRENT_TIMESTAMP	摘要生成时间
    5. updated_at	TIMESTAMP    DEFAULT CURRENT_TIMESTAMP	摘要更新时间
3. `facts`**（结构化事实）**：`id`, `category`, `content`, `confidence`, `updated_at`。存储用户偏好、习惯等。
    1. id	INTEGER	PRIMARY KEY AUTOINCREMENT	事实唯一ID
    2. category	TINYINT	NOT NULL	分类,默认0preference，1event，2profile（如 'preference', 'event', 'profile'）
    3. content	TEXT	NOT NULL	事实内容（如 '用户讨厌吃香菜'）
    4. confidence	REAL	DEFAULT 1.0	置信度（0-1，防止 AI 幻觉记错事）
    5. created_at	TIMESTAMP	DEFAULT CURRENT_TIMESTAMP	创建时间
    6. updated_at	TIMESTAMP	DEFAULT CURRENT_TIMESTAMP	最近一次被提及或更新的时间
4. `vec_memory`**（向量记忆）**：虚拟表，`rowid`, `embedding`(BLOB), `source_text`。通过 `sqlite-vec` 扩展实现语义检索。
    1. rowid	INTEGER	PRIMARY KEY	隐式主键，可关联 facts 或 messages 的 id
    2. embedding	BLOB	NOT NULL	文本经过 Embedding 模型处理后的浮点数组（如 1536 维）
    3. source_text	TEXT	NOT NULL	原始文本块（用于检索后直接拼接入 Prompt）
5. `pet_states`**（桌宠状态）**：`affection_points`（好感度）, `relationship_level`（关系等级）, `last_interaction`, `last_decay_at`, `active_renderer`。
    1. id	INTEGER	PRIMARY KEY	固定为 1，单用户单角色
    2. pet_name	VARCHAR(20)	DEFAULT '喵喵'	桌宠名字
    3. relationship_level	INTEGER	DEFAULT 1	关系等级（1:陌生, 2:熟人, 3:亲密）
    4. affection_points	INTEGER	DEFAULT 0	好感度积分（通过互动增加、减少）
    5. last_decay_at	DATETIME	NULL	上次执行衰减结算的时间
    6. active_renderer	TEXT	DEFAULT 'code_cat'	当前使用的渲染器（未来扩展自定义形象用）
    7. renderer_config	JSON	NULL	渲染配置 JSON 字符串（如背景色、图片路径）
    8. last_interaction	TIMESTAMP	NULL	上次互动时间（用于计算空闲时间）
6. `affection_logs`**（好感度流水）**：记录加减分原因，用于每日上限校验和防刷。
    1. id	INTEGER	PRIMARY KEY AUTOINCREMENT	流水ID
    2. change_value	INTEGER	NOT NULL	变化值（正数增加，负数减少）
    3. reason	TEXT	NOT NULL	变动原因（如 'daily_interaction', 'long_absence', 'chat_reward'）
    4. created_at	TIMESTAMP	DEFAULT CURRENT_TIMESTAMP	发生时间
7. `**<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">app_settings</font>**`**<font style="color:rgb(15, 17, 21);">（全局配置 ）</font>**<font style="color:rgb(15, 17, 21);">：</font>`<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">key</font>`<font style="color:rgb(15, 17, 21);"> (主键), </font>`<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">value</font>`<font style="color:rgb(15, 17, 21);">。用于存储 API 配置和勿扰时段</font>
    1. <font style="color:rgb(15, 17, 21);">id	INTEGER	PRIMARY KEY AUTOINCREMENT	全局配置编号</font>
    2. <font style="color:rgb(15, 17, 21);">type  INTEGER	DEFAULT 1 配置下类型（1大模型，2勿扰时段，其他待定）</font>
    3. <font style="color:rgb(15, 17, 21);">is_custom_quota_used INTEGER	DEFAULT 1 是否使用了内置体验额度（默认1使用，2不使用）</font>
    4. <font style="color:rgb(15, 17, 21);">value	JSON	NULL	配置项值（JSON 字符串），可以设置多个勿扰时段和LLM</font>
        1. <font style="color:rgb(15, 17, 21);">llm_base_url: API 地址（默认 </font>[https://api.openai.com/v1）](https://api.openai.com/v1）)
        2. llm_api_key: 密钥
        3. llm_model_custom: 模型自定义名称（如 gpt-4o-mini）
        4. llm_model: 模型名称（如 gpt-4o-mini）
        5. dnd_enabled: 是否开启勿扰（true / false）
        6. dnd_start_time: 勿扰开始时间（如 09:00）
        7. dnd_end_time: 勿扰结束时间（如 18:00）
8. `**<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">diaries</font>**`**<font style="color:rgb(15, 17, 21);">（日记表）</font>**<font style="color:rgb(15, 17, 21);">：</font>
    1. <font style="color:rgb(15, 17, 21);">id INTEGER PRIMARY KEY AUTOINCREMENT 日记编号</font>
    2. <font style="color:rgb(15, 17, 21);">diary_date DATE UNIQUE NOT NULL 记录哪一天的日记</font>
    3. <font style="color:rgb(15, 17, 21);">content TEXT NOT NULL 日记正文（第一人称）</font>
    4. <font style="color:rgb(15, 17, 21);">mood INTEGER 当天的情绪状态</font>
    5. created_at	TIMESTAMP	DEFAULT CURRENT_TIMESTAMP	创建时间
    6. <font style="color:rgb(15, 17, 21);">updated_at	TIMESTAMP	DEFAULT CURRENT_TIMESTAMP	更新时间</font>

### 5.2 记忆管道工作流（不阻塞对话）
+ **对话中**：用户输入 -> 去 `vec_memory` 和 `facts` 检索 -> 拼装 Prompt -> 流式请求 LLM -> 渲染气泡并触发 TTS。
+ **后台异步沉淀**：对话结束后，触发后台任务让廉价模型提取新事实并生成摘要，计算向量后写入数据库。

### **<font style="color:rgb(15, 17, 21);">5.3 Schema 版本管理与迁移策略</font>**
+ **<font style="color:rgb(15, 17, 21);">版本追踪</font>**<font style="color:rgb(15, 17, 21);">：使用 SQLite 内置 </font>`<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">PRAGMA user_version</font>`<font style="color:rgb(15, 17, 21);"> 记录 schema 版本，不额外创建版本表</font><font style="color:rgb(15, 17, 21);">。</font>
+ **<font style="color:rgb(15, 17, 21);">迁移工具</font>**<font style="color:rgb(15, 17, 21);">：Rust 侧使用 </font>`<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">rusqlite_migration</font>`<font style="color:rgb(15, 17, 21);"> crate，定义有序迁移链，启动时自动前向迁移</font><font style="color:rgb(15, 17, 21);">。</font>
+ **<font style="color:rgb(15, 17, 21);">迁移原则</font>**<font style="color:rgb(15, 17, 21);">：</font>
    - <font style="color:rgb(15, 17, 21);">优先</font>**<font style="color:rgb(15, 17, 21);">加量式迁移</font>**<font style="color:rgb(15, 17, 21);">（</font>`<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">CREATE TABLE IF NOT EXISTS</font>`<font style="color:rgb(15, 17, 21);">、</font>`<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">ADD COLUMN</font>`<font style="color:rgb(15, 17, 21);">），保证幂等。</font>
    - <font style="color:rgb(15, 17, 21);">需要删除/重命名列时，走“新建表 → 数据搬迁 → DROP → 重命名”路径，全程事务包裹</font><font style="color:rgb(15, 17, 21);">。</font>
    - <font style="color:rgb(15, 17, 21);">每个迁移在独立事务中执行，失败自动回滚</font><font style="color:rgb(15, 17, 21);">。</font>
+ **<font style="color:rgb(15, 17, 21);">版本不匹配处理</font>**<font style="color:rgb(15, 17, 21);">：</font>
    - `<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">user_version ></font>`<font style="color:rgb(15, 17, 21);"> 应用期望版本：</font>**<font style="color:rgb(15, 17, 21);">失败关闭</font>**<font style="color:rgb(15, 17, 21);">，提示用户升级应用。</font>
    - `<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">user_version <</font>`<font style="color:rgb(15, 17, 21);"> 应用期望版本：执行前向迁移，迁移前自动备份 </font>`<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">.db</font>`<font style="color:rgb(15, 17, 21);"> 文件。</font>
+ **<font style="color:rgb(15, 17, 21);">sqlite-vec 升级兼容</font>**<font style="color:rgb(15, 17, 21);">：</font>`<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">vec_memory</font>`<font style="color:rgb(15, 17, 21);"> 视为</font>**<font style="color:rgb(15, 17, 21);">可重建的派生表</font>**<font style="color:rgb(15, 17, 21);">，扩展升级若导致虚拟表不兼容，在迁移中删除重建，从 </font>`<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">facts</font>`<font style="color:rgb(15, 17, 21);"> / </font>`<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">messages</font>`<font style="color:rgb(15, 17, 21);"> 重新生成 embedding，不丢失用户记忆。</font>

## 七、 好感度与关系系统
### 6.1 关系等级界定
| 等级 | 名称 | 积分区间 | 表现 |
| :--- | :--- | :--- | :--- |
| Lv.1 | 陌生 | 0 - 200 | 礼貌、克制。 |
| Lv.2 | 熟人 | 201 - 500 | 轻松，偶尔开玩笑。 |
| Lv.3 | 亲密 | 501 - 800 | 撒娇，表达想念。 |
| Lv.4 | 羁绊 | 801 - 1000 | 老夫老妻，直接指出不良习惯。 |


### 6.2 积分与衰减机制（弹性惩罚）
+ **加分**：每日打卡 +10；互动 +1（日上限 20）；深度对话 +5；共鸣加分 +10~20。
+ **减分**：超过 3 天未打开，每天 -5，**扣除至当前等级下限即停止**（防挫败）；恶意辱骂单次 -10~30。
+ **引擎逻辑**：应用启动时读取 `last_decay_at` 结算衰减；对话后置 LLM 判定是否触发额外加分/扣分。
+ **<font style="color:rgb(15, 17, 21);">强调</font>**<font style="color:rgb(15, 17, 21);">：所有在减分/冷落状态下的主动互动，Prompt 必须转化为“情绪表达”（如：吃醋、委屈），</font>**<font style="color:rgb(15, 17, 21);">绝对禁止向用户播报冰冷的数值变化</font>**<font style="color:rgb(15, 17, 21);">。</font>

## 八、 性能与隐私红线
+ **性能指标**：待机状态下，CPU 占用 `< 2%`，内存占用 `< 150 MB`（PIXI 待机可降至 30fps）。
+ **隐私底线**：MVP 阶段**绝不接入主动截图**。所有记忆数据经 SQLCipher 本地加密。大模型请求走用户自备 API Key。
