## 一、关键裁决（登记勘误 #21）

| # | 问题 | 裁决 |
| :--- | :--- | :--- |
| 1 | **卸载是否删除用户数据（pet.db）** | **保留**：卸载不删除用户数据目录（SQLCipher 全库加密，无明文泄露风险；日记/记忆对用户有情感价值）——NSIS 卸载配置明确"保留用户数据"并在卸载页提示路径；提供手动清理说明 |
| 2 | **自动更新** | **MVP 不引 updater 插件**（无更新服务端，属外部依赖）：版本号/产品信息写规范即可；更新检查登记 Phase 2（复用内置额度外部端点体系可扩展） |
| 3 | 首次启动引导形态 | **轻量气泡欢迎**（非多步向导）：首次启动 emit 欢迎语（内置额度说明 + 快捷键提示），标记文件 `app_data_dir/.first_run_done`（文件标记，零 DB 迁移）；计费说明入口已在 D2 面板（选型规则） |
| 4 | CSP 初版策略 | `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; style-src-attr 'unsafe-inline'; font-src 'self'; img-src 'self' data: blob:`——LLM 请求全在 Rust 侧（WebView 无外联），connect-src 仅需 IPC 通道（Tauri 自动处理）；**以 G2 打包产物实测为准微调** |
| 5 | devtools | 生产构建关闭 devtools（`tauri.conf.json` 或 feature gate），开发构建保留 |
| 6 | 版本策略 | 首发版本 `0.1.0`（MVP）+ git tag；SemVer，Phase 2 功能走 0.x |

## 五、风险与回退

| 风险 | 对策 |
| :--- | :--- |
| CSP 收紧误杀运行时资源（字体/data URL/内联样式） | 初版策略保守 + 打包产物控制台逐资源排查；逐项放开并记录理由（禁止直接 `unsafe-eval` 大撒把） |
| SmartScreen/无签名拦截安装 | README/首启引导明确说明"更多信息→仍要运行"；代码签名证书登记 Phase 2（成本项） |
| 干净环境缺失（无 VM） | 备用方案：本机清理用户数据目录 + 新建 Windows 用户账户模拟；残留风险登记 |
| 卸载保留数据引发用户困惑 | 卸载页 + README 双处说明路径与手动清理方法 |
| 打包后性能回退（release profile 行为差异） | G2.2 走查中复测待机 CPU/内存（E2 快测口径）；超标回退分析 release 配置 |
| G4 预留核对发现接口缺口（如 renderer_config 结构未定） | 小缺口当场补（结构文档化）；大缺口登记 Phase 2 并如实标注"部分预留" |
