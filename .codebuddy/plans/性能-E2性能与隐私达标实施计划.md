## 一、关键裁决（登记勘误 #17：测量口径）

| # | 问题 | 裁决 |
| :--- | :--- | :--- |
| 1 | **内存 150MB 的口径**：Tauri 进程树 = Rust 主进程 + 2 个 WebView2 进程（窗口 A/B 各一），任务管理器只看主进程会严重低估 | 口径 = **进程树私有工作集总和**（主进程 + qiqi WebView2 进程们）；工具：PowerShell `Get-Process` 按进程名聚合（脚本进 `scripts/perf-snapshot.ps1`）+ 任务管理器"详细信息"页复核 |
| 2 | CPU 2% 基准 | 任务管理器/Get-Process 的 **CPU%（全机基准）**，取待机 10 分钟均值（排除启动峰值）；同步记录单核占比做参考 |
| 3 | "待机"定义 | 窗口 A 可见、无鼠标悬停/交互、无对话进行、非勿扰休眠——即常态挂机 10 分钟 |
| 4 | 超标修复顺序 | 按嫌疑度：① PIXI 待机帧率 ② 探针轮询频率 ③ 事件 emit 频率 ④ 内存泄漏（监听/定时器/任务句柄）——**逐项单独修复 + 复测**（不合并，保证归因） |
| 5 | 测量环境登记 | 记录硬件（CPU 核数/内存）、系统版本、电源计划、显示刷新率——数据可复现 |

## 三、测量矩阵（六场景）

| # | 场景 | 操作 | CPU 目标 | 内存目标 | 备注 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| M1 | 冷启动峰值 | 启动后 30s 内 | 记录峰值 | 记录峰值 | 仅记录，不设红线 |
| M2 | **待机 10min** | 常态挂机无交互 | **均值 < 2%** | **< 150MB** | 核心验收 |
| M3 | 对话流式中 | 连续 3 轮流式对话 | 记录（无硬红线，观察尖峰回落） | < 150MB + 记录 | 打字机/节流效果验证 |

## 四、隐私合规核对清单（E2.5，逐项留档）

| # | 红线 | 核对方法 | 通过标准 |
| :--- | :--- | :--- | :--- |
| 1 | **零截图** | grep Rust/前端：`PrintWindow`/`BitBlt`/`CopyFromScreen`/`capture`/`screenshot` 零命中 | 无任何屏幕采集路径 |
| 2 | **全库加密** | 无密钥打开 `pet.db` 报密文错误（复测 B4 用例 5）+ 文件头非明文 SQLite（`hexdump` 首页无 "SQLite format 3"） | 双重验证 |

## 五、PIXI 待机降帧实现要点（E2.3 ①，若需）

```
C6 idle 状态机（probe:idle:changed）
  ├─ idle 进入 → renderer.setIdleMode(true)  → app.ticker.maxFPS = 30
  └─ active 回归 → renderer.setIdleMode(false) → app.ticker.maxFPS = 60
```

- `IPetRenderer` 增可选方法 `setIdleMode(enabled)`（契约微调，登记勘误 #18）——仅接口扩展，Mock 同步
- 勿扰/吸附休眠复用 idle 通道（休眠态 = idle 帧率 + 主动静默）
- 转换时呼吸相位连续（不停表，只降上限）——避免视觉跳变

## 七、风险与回退

| 风险 | 对策 |
| :--- | :--- |
| WebView2 进程内存为黑盒（共享/私有难分） | 用私有工作集口径 + 同方法前后对比（绝对值偏差不影响相对优化判断） |
| 待机 CPU 由 WebView2 定时器/合成器贡献而非应用代码 | 逐一关闭验证（停 ticker/停轮询做对照实验），归因后精准修复 |
| 降帧引入视觉卡顿（E3 打磨冲突） | 30fps 仅待机态；对话/交互即时恢复 60fps；E3 主观复核兜底 |
| 性能修复与 E1b 联调缺陷修复冲突 | 逐项独立 commit（auto-commit）保证可回退；修复前基线数据已存档 |
| 测量受后台任务干扰（系统更新/杀毒扫描） | 测量前关闭高负载程序、记录异常采样并重测 |

## 八、执行顺序

E2.1（测量脚本）→ E2.2（六场景实测）→ 分支：达标 → 直跳 E2.5 隐私核对；超标 → E2.3/E2.4 逐项修复复测 → E2.5 → DoD 收口（**M2 达成**）→ E3 衔接。
