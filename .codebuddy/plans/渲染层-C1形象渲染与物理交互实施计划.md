## 三、形象拆解与分层（baseline §4.1 / 设计稿 §五）

```
stage (Application.stage)
└── petRoot (Container，pivot 居中——果冻缩放围绕中心)
    ├── bodyG      # 身体：圆角矩形/椭圆，--matcha；含脚部省略（极简）
    ├── faceG      # 面部：白色大椭圆 + 小椭圆刘海
    ├── earL / earR# 两个三角形
    ├── tailG      # 尾巴：Bezier 曲线绘制一次，pivot 在根部，每帧仅 rotation（性能红线）
    └── eyesG      # 眼睛容器：两枚黑色胶囊（Graphics 圆角矩形）；lookAt/眨眼/表情作用于此
```

**性能决策**（rule.md §4.3 红线）：所有图形**绘制一次**；每帧只改 transform（scale/rotation/position）——帧内零 `new` 对象、零 Geometry 重建；临时变量在类字段声明循环外复用。尾巴贝塞尔是静态形状，摇摆用旋转近似（若 E3 体验打磨期不满意再评估重绘方案）。

## 四、动画算法（公式来源：baseline §D / `桌宠.md` §4.2，`physics.ts` 已实现）

| 动画 | 公式 | 实现要点 |
| :--- | :--- | :--- |
| 待机呼吸 | `breath = sin(t) * 0.03` → `[1 - breath*0.5, 1 + breath]` | `t` 用 ticker deltaMS 累积（循环外变量）；sleep 态幅度 ×0.5 |
| 点击果冻 | 瞬间 `scaleX=1.15 / scaleY=0.85` | `jellyImpulse()`，随后每帧 `dampedRecovery` 回弹 |
| 阻尼回弹 | `val += (1 - val) * 0.1` | 每帧对 scaleX/scaleY 各调一次，收敛到 1 |
| 拖拽形变 | `stretch = min(hypot(dx,dy) * 0.01, 1.5)` → `scaleX=1+stretch / scaleY=1-stretch*0.5` | 按 drag 方向轴向施加（C2 接入后启用；本计划实现函数并留接口） |
| 视线跟随 | 眼睛容器偏移限幅 3–5px | `eyeOffset(cursor, center, 5)`，Ticker 内应用 |
| 眨眼 | 周期 3–5s 随机，`scaleY` 快速 0→1 | 低频计时器，同一 Ticker 内累计 |

注意：果冻缩放必须围绕角色中心 → `petRoot.pivot` 设为形心；缩放叠加顺序 = 果冻(scale) × 呼吸(微扰)，两者相乘而非覆盖。

## 九、风险与回退

| 风险 | 对策 |
| :--- | :--- |
| PIXI 8 API 与 v7 差异（初始化/`resizeTo`） | 实现前核对 PIXI 8 官方文档（`Application.init()` 异步 promise 形态）；伪代码先确认再写完整实现（development-guide 工作流） |
| 果冻缩放中心偏移视觉异常 | `petRoot.pivot` 取 `getBounds()` 形心，挂载时计算一次 |
| 每帧重绘导致 CPU 超标 | 强制 transform-only 动画（§三 性能决策）；出现重绘需求一律先改设计再写码 |
| 多 Ticker（组件重挂载） | factory 单例 + `usePetRenderer` 卸载即 dispose；dev 热更新后手工复查 ticker 数量 |
| 眼睛"弯弧"近似不达预期 | E3 体验打磨处理：届时评估预渲染两帧眼睛贴图切换（仍是零美术资源的代码生成） |
