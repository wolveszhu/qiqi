## 一、关键裁决（登记勘误 #9：规则量化口径）

| # | 文档原文模糊点 | 裁决（MVP 口径，常量集中于 `affection/rules.rs`，可调） |
| :--- | :--- | :--- |
| 1 | "打卡 +10"未定义判定 | 每日首次互动 +10：任一互动触发 settle 时，检查当日 `affection_logs` 是否已有 `daily_check_in`，无则 +10；由前端启动时（PetWindow mount）显式调 `pet_settle_affection("check_in")` |
| 2 | "抚摸 +1 日上限 20" | 当日 `reason='pet_stroke'` 的 `change_value` 合计 < 20 才生效（单次 +1，至多补到 20）；抚摸入口 = 窗口 A 双击/长按（C1 `playAction` 联动，触发命令由 D1/C2 接线，本计划提供命令） |
| 3 | "深度对话 +5"未定义"深度" | **MVP 量化**：单轮对话中 assistant 回复字数 ≥ 80 或该 session 累计轮次 ≥ 5 → 记一次深度对话（同 session 去重，每 session 最多 1 次）；阈值常量可调，C4 done 时携带字数调用 settle |
| 4 | "共鸣 +10~20"判定方式 | **复用 C4 蒸馏管道**：done 后 distill 扩展一步——memory 档小模型判定本轮是否产生情感共鸣（输出 `{resonance: 0\|1, strength: 1\|2}`）→ strength 1→+10、2→+20；解析失败/未判定 → 不加分（静默，同 C4 沉淀策略） |
| 5 | 衰减锚点语义 | `last_interaction` = 未互动起点；`last_decay_at` = 上次结算时间（防重复扣）。结算区间 `[max(last_decay_at, last_interaction+3d), today)` 内每一天 -5；首次（last_decay_at NULL）从 `last_interaction+3d` 起算 |
| 6 | 结算触发点 | ① `lib.rs` setup 启动结算（异步，防重复：结算幂等）；② `pet_get_state` 懒结算兜底（跨天未重启场景） |

## 四、情绪表达映射（禁播报数值的实现口径）

| 变化 | 表现（窗口 A） | 数值可见范围 |

## 八、风险与回退

| 风险 | 对策 |
| :--- | :--- |
| 共鸣判定依赖 LLM 输出不稳定 | 宽松解析 + 失败静默不加分（宁少不多）；阈值/开关常量化可关闭该信号 |
| 深度对话阈值误判（刷分） | 每 session 去重 + 字数阈值常量；刷分收益天然受日上限类约束（抚摸 20、打卡唯一），深度对话暂不限次——登记观察项，E 联调评估加日上限 |
| 跨天结算时区问题 | 统一用 `Local` 日期（chrono Local 日期），"当日"按用户本地时区；单测注入固定日期 |
| 启动结算阻塞启动 | spawn 异步 + 失败仅 log，不阻断窗口 |
| 与 C7 禁忌并发写 states | 同一 Mutex<Connection> 串行化天然安全；事务短小 |

### 关键 API 实态修正（编译/测试驱动）

1. `AppHandle` 不来自 `State::app_handle()`（Tauri 2 无此 API）→ 命令增 `app: AppHandle` 参数。
2. `settle_signal` 拆分 core/emit：`AppHandle` 在集成测试中不可构造，core 版供 `tests/affection_it.rs` 验证事务性（结算后 states 与 logs 同步、重复打卡不重复加、封顶 1000、跨天衰减止档 + 幂等）。
3. `delta == 0` 的重复打卡/达上限抚摸**不再写流水**（避免污染 D2 看板）；衰减（负 delta）照常写 `long_absence` 流水。
4. `affection` 模块由 `mod` 改 `pub mod`（集成测试跨 crate 访问）；`Cargo.toml` 增 `chrono`（日期/天数差，已在 lock 中无需联网）。
5. C4 `prompt.rs` 改用 `affection::level::behavior_prompt` 注入等级指令（单一真源，去重 `RELATION_LEVEL_DIRECTIVES` 直接引用）。
