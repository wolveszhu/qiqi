## 三、F3/F4 发现的缺陷（详见 `E1a-联调问题清单.md`）

| 编号 | 级别 | 摘要 | 状态 |
| :--- | :--- | :--- | :--- |
| F3-001 | **P1** | `affection_logs::todays()` 时区口径错误：`created_at` 为 UTC 未转本地 → UTC+8 本地 00:00–08:00 当日打卡可重复、抚摸日上限失效 | **已修** + 回归钉子 |
| F3-002 | P2 | 新库 type=2 种子为旧单段格式，frequency 持久化空串（勘误 #13 清理项） | **已修**（M4 迁移）+ 3 项测试 + 真实启动验证 |
| F3-003 | 登记 | 环境类场景（R1/R2/R7/R9）本环境不可执行 | 待真机（见 §一） |

### F3-001 发现过程（回归价值实证）

执行 R6 相关 Rust 集成测试时，`settle_is_transactional_logs_and_states_uniqueness`（当日重复打卡应返回 0）在**本地 00:49** 失败：第二次打卡返回 +10。

初判为"午夜边界抖动"，复跑仍失败 → 排查 `created_at DEFAULT CURRENT_TIMESTAMP`（UTC）与 `date('now','localtime')`（本地）比较 → 实测系统 UTC+8（本地 00:50 = UTC 16:50 前一天）→ **坐实为真实缺陷**：UTC+8 用户每天本地 00:00–08:00 的 8 小时内打卡唯一性与抚摸日上限失效。

代码库内早有正确约定（`messages::by_date` 注释明示"`created_at` 为 UTC，按 `date(created_at,'localtime')` 过滤"），唯独 `affection_logs.rs` 遗漏——属单点遗漏而非设计缺陷。修复一词之差（`date(created_at)` → `date(created_at, 'localtime')`）。

> **若不做真实时序回归，此缺陷会随发布进入所有 UTC+8 用户的夜间时段。**

### F3-002 附带发现（过程自查）

M4 迁移首版用 `COALESCE(json_extract(...), 0)` 写 `enabled`，生成 JSON **整数 0**，而 `DndValue.enabled: bool` 反序列化失败 → settings 读取全断（3 个既有测试失败暴露）。即时改为 `json('true'/'false')`，并以"迁移后 `SettingsDndValue` 端到端反序列化"断言钉死。**这是"修复即配回归钉子"的实证。**

## 四、二进制命名坑（回归方法学记录）

`cargo build` 产物二进制名为 **`七七.exe`**（包名"七七"），而 `target/debug/qiqi.exe` 是历史遗留的**陈旧二进制**（10-20 22:34）。前两次冒烟启动误用 `qiqi.exe`，导致"应用启动正常"的结论实际基于三天前的旧代码。

**教训与固化**：真机/二进制级回归必须先校验产物时间戳。本记录 §二 R12 的结论基于 `七七.exe`（构建时间 2026-10-23 00:56）重新执行，方为有效。
