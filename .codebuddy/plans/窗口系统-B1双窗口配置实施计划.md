## 三、窗口规格（写入 `tauri.conf.json` 的目标形态）

```
app.windows:
  ① label "main"（窗口 A · 桌宠层）
     width 400, height 400, minWidth/minHeight 400
     transparent: true, decorations: false, alwaysOnTop: true,
     skipTaskbar: true, resizable: false, center: true, visible: true
  ② label "settings"（窗口 B · 设置层）
     width 1000, height 660, minWidth 900, minHeight 620
     transparent: false, decorations: false（自绘 TitleBar，回退见 §五）,
     alwaysOnTop: false, skipTaskbar: false, center: true,
     visible: true（开发期策略，C2 托盘到位后改 false）, title: "七七 · 设置"
```

要点：
- **label 是前后端契约**：`main.ts` 分发、Rust 侧 `get_webview_window("main"/"settings")` 均以此为准——命名入 `window/manager.rs` 常量（不写魔法字符串，冷眼三问之"无写死路径"）。
- 窗口 A `resizable:false`：文档定死 400×400 逻辑像素，避免缩放破坏果冻缩放中心与 hitRegion 计算。
- 窗口 A `transparent:true` 依赖 WebView2 透明合成——Win10 需 DWM 合成开启（默认开启；风险表留回退）。
- CSP 维持 `null`（开发期），G1 收紧——本计划不触碰。
- 图标/identifier 等发布配置属 G1，不动。

## 六、风险与回退

| 风险 | 对策 |
| :--- | :--- |
| Win10 关闭 DWM/合成器异常导致透明失效 | 检测 `transparent` 失效时降级不透明纯色背景（视觉可接受），登记已知问题；核心穿透逻辑不受影响（C2） |
| `decorations:false` 自绘标题栏圆角/阴影异常（设计方案 §5.0） | 回退：窗口 B 改原生 `decorations:true`，仅保留关闭=hide 拦截——配置一处改动 |
| 透明窗口整窗可点（穿透未做） | 属 C2 范围；B1 阶段文档注明"整窗接收点击为预期中间态"，避免误判为缺陷 |
| 多窗口 dev 下 HMR 状态串扰 | 两窗口独立 WebView 实例，理论隔离；出现串扰按 label 检查分发逻辑 |
| `prevent_close` 误拦窗口 A 导致无法退出开发进程 | dev 期用托盘/任务管理器结束；C2.6 托盘退出走 Rust 侧 `app.exit`（绕过事件拦截） |
