# 远程更新（轻量自建）实施计划

> 状态：已实现（2026-11-04）。本文件为计划快照，供后续追溯。
> 关联代码：`src-tauri/src/commands/update.rs`、`src/api/update.ts`、`src/composables/useUpdate.ts`、`src/views/settings/panels/AboutPanel.vue`、`src/components/settings/UpdateNotice.vue`。

## 1. 目标

为桌面应用「七七」实现轻量自建的远程更新能力：当 GitHub 仓库发布新版本时，客户端能检测到更新并弹出提醒，用户可点击跳转下载安装包（手动运行），**无需代码签名证书、无需自建发布服务器、不引入 `tauri-plugin-updater`**。

## 2. 选型（已与用户确认）

- **机制**：轻量自建——Rust 后台轮询版本接口 + 弹提醒 + 下载按钮，用户手动运行安装包。
- **托管**：GitHub Releases（仓库根维护 `latest.json` + `.msi` 安装包）。
- **时机**：启动后延迟 ~10s 首查 + 每 ~6h 周期静默查 + 设置页「关于」Tab 手动「检查更新」。

## 3. 数据契约：`latest.json`

托管于仓库根，经 `raw.githubusercontent.com/wolveszhu/qiqi/main/latest.json` 稳定读取（免 API 限流、免 token）。

```json
{
  "version": "0.1.0",
  "notes": "更新说明（多行）",
  "downloadUrl": "https://github.com/wolveszhu/qiqi/releases/download/v0.2.0/qiqi_0.2.0_x64_en-US.msi"
}
```

- `version`：纯语义化版本号（**不含 `v` 前缀**，否则无法解析为 semver）。
- `downloadUrl`：GitHub Releases 的稳定 `latest` 资产或具体版本资产 URL。
- 当前版本取自编译期 `env!("CARGO_PKG_VERSION")`（= `tauri.conf.json` 的 `version`）。

## 4. 后端（`src-tauri`）

- 新增 `commands/update.rs`：
  - `UpdateInfo { available, current, latest, notes?, downloadUrl? }`（`camelCase` 序列化，与前端契约对应）。
  - `fetch_latest()`：reqwest 拉取 + 5s 超时 + 合理 UA；失败向上传播 `AppError::Llm`。
  - `detect()`：semver 比较；远端版本不可解析时**回落「无更新」**（宁可漏报不误报）。
  - `#[tauri::command] check_update()`：手动/后台共用入口。
  - `spawn_update_checker(app)`：`.setup()` 中以 `tauri::async_runtime::spawn` 起循环（首查延迟 10s → 检查 → sleep 6h）；发现更新 `app.emit("app:update-available", UpdateInfo)`；循环内一切错误吞掉（`release` 为 `panic="abort"`，绝不让检查任务 panic 拖垮进程）。
- `Cargo.toml`：新增 `semver = "1"`。
- `commands/mod.rs`：`pub mod update;`。
- `lib.rs`：`invoke_handler` 注册 `check_update`；`.setup()` 调用 `spawn_update_checker`。
- `capabilities/default.json`：显式加 `opener:allow-open-url`（打开下载链接）。

## 5. 前端（`src`）

- `api/update.ts`：`checkUpdate()` 封装 + `UpdateInfo` 接口（走 `callCommand`）。
- `composables/useUpdate.ts`：单例响应式状态（`updateInfo`/`checking`/`lastError`/`hasUpdate`）+ `checkNow()`/`dismiss()` + 幂等注册 `app:update-available` 监听器（`initUpdateWatcher()` 在设置窗口挂载时调用一次）。
- `views/settings/panels/AboutPanel.vue`：「关于」Tab——当前版本、检查更新按钮、状态文案、更新卡片（版本/说明/下载/复制链接/稍后），切回 Tab 时（`onActivated`）主动再查一次。
- `components/settings/UpdateNotice.vue`：非阻塞横幅（设置窗口顶部），`hasUpdate` 时展示，可「下载更新」或「稍后」忽略。
- `components/window/SideNav.vue`：增加「关于」Tab + `hasUpdate` 常驻小标记。
- `views/settings/SettingsWindow.vue`：注册 About Tab、`initUpdateWatcher()`、渲染 `UpdateNotice`。

## 6. 边界与红线

- 只做「提醒 + 跳转下载」，不自动下载/静默安装（规避代码签名与 UAC 复杂度）。
- 网络失败/404/解析失败：后台检查静默跳过；手动检查给友好提示，不弹错误、不写日志噪音。
- 不引入新 Tauri 插件；自定义命令免 capability 授权；打开外链复用 `opener:default` + 显式 `allow-open-url`；事件收发权限已具备。

## 7. 发布流程（运维）

1. 本地 `pnpm tauri build` 得到安装包（MSI/NSIS）。
2. 在 GitHub 仓库 **Releases** 上传安装包。
3. 更新仓库根 `latest.json`：`version` 改为新版本号、`downloadUrl` 指向该安装包；保持与 `tauri.conf.json` 的 `version` 同步。
4. 提交并推送（raw URL 自动生效）。

### 7.1 仓库可见性要求（重要）

清单源（raw.githubusercontent / jsDelivr CDN）均为**匿名**读取——**仓库必须为 Public**：
GitHub 对私有仓库的匿名 raw/CDN/API 请求一律返回 404（故意不区分"私有"与"不存在"），
客户端将报「HTTP 404——清单不存在」。若需保持私有，须更换托管（如 Gitee 公开仓库、
自建/对象存储），并同步修改 `update.rs` 的 `LATEST_JSON_URLS`。

客户端按序回退三个源：raw（即时性最好）→ cdn.jsdelivr.net → fastly.jsdelivr.net
（后两者为国内网络对 raw 阻断/污染时的兜底；jsDelivr 对分支引用有最长 12h 缓存，
发版日可能滞后，可通过 `https://purge.jsdelivr.net/gh/<owner>/<repo>@main/latest.json` 强刷）。

## 8. 验证

- 后端：`cargo test --lib update` 全过（解析 + semver 比较，含「非法版本回落无更新」）。
- 前端：`pnpm typecheck` 通过；`tauri dev` 后于「关于」Tab 点「检查更新」可见状态；将 `latest.json` 的 `version` 临时调高于本地版本并重启→设置窗口出现更新横幅与 Tab 标记。
