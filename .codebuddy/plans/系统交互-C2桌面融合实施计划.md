## 三、架构设计细节

### 3.1 探针单点原则（规范 §4 硬约束）

```
probe/cursor.rs（唯一 GetCursorPos 轮询，100ms）
   ├─ emit "probe:cursor:move" → 窗口 A lookAt（C1/B5 消费）
   └─ 更新进程内 cursor 缓存 → click_through 线程消费（不走事件，零 IPC）
```

`GetCursorPos` 全应用只允许出现一次；穿透判断用进程内缓存而非事件，避免事件洪泛。

### 3.2 穿透状态机

```
状态：ignore=true（默认，透明区可穿透） ⇄ ignore=false（悬停猫身）
输入：cursor 缓存坐标 ∩ hitRegion 缓存（前端上报，AppState 持有）
规则：仅状态翻转时调用 set_ignore_cursor_events（每 100ms 轮询最多一次系统调用）
兜底：窗口 A 失焦/隐藏 → 强制 ignore=true；勿扰总闸开 → 强制 true
```

hitRegion 判定用**窗口局部坐标**：`窗口位置 + 命中矩形` vs 全局 cursor（窗口位置经 `outer_position()` 获取，窗口未移动时缓存）。

### 3.3 拖拽链路（系统接管，rule §5 红线）

`pointerdown`（命中猫身才触发）→ `window_start_drag` → `WebviewWindow::start_dragging()`——移动、跨屏、DPI 均由 OS 处理；前端只负责形变反馈（`playAction("drag")` + `physics.stretchFactor`，C1 已实现）与松手回弹。

### 3.4 错误与边界（code-standards §4/§5）

- 所有命令 `Result<T, AppError>`，`?` 传播；Win32 调用失败映射 `AppError::Probe`；禁 `unwrap/expect` 处理业务错误。
- 后台线程退出：`app.handle().clone()` 持有，应用退出时随进程结束；轮询线程内禁止 panic（判空保护）。
- 命令命名动词开头 snake_case（`window_start_drag`、`window_set_hit_region`），capabilities 逐项最小授权。
