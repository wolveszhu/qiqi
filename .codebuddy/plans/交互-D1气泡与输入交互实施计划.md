## 三、附件 DTO 扩展（勘误 #2 的契约增量）

```ts
// types.ts 增量（与 Rust serde 对齐）
interface FilePayload {
  name: string;                    // 展示名
  kind: "text" | "image";
  /** text=utf8 内容；image=base64 dataURL（不含 mime 前缀重复） */
  content: string;
  mime: string;                    // image/png 等
}
// chat_send_stream 请求增可选字段（向后兼容）
{ sessionId: string; text: string; attachments?: FilePayload[] }
```

Rust 侧：C4 `chat` 命令实装时将 `attachments` 映射为 OpenAI vision `content` 数组（text part + image_url dataURL part）；纯文本消息保持既有形态。事件契约（delta/done/error）**不变**。

### 关键 API 实态修正（编译驱动）

1. **vision content 改造**：`llm/client.rs` 的 `ChatMessage.content` 由 `String` 改为 `MessageContent`（untagged：`Text(String)` | `Parts(Vec<ContentPart>)`），新增 `ContentPart`/`ImageUrl`；`as_text()` 提取落库文本（图片不持久化，MVP 记忆不存图）。C4 实装时未含此扩展，D1 一并落地（裁决 #2）。
2. **`chat_send_stream` 改 attachments 必填**（非 `#[serde(default)]`）：Tauri 命令宏在 fn 参数上的 `#[serde(default)]` 属性在当前 tauri 版本解析失败，**前端恒传 `attachments: []`** 保持向后兼容（等价可选）。
3. **D1.5 DragDrop 改用 Tauri 内置事件**：`WindowEvent::DragDrop` 是元组变体（Tauri 已向 webview 发 `tauri://drag-drop` 事件），**不再手写 `window/manager.rs` emit**（避免与框架重复实现）；前端 `listen("tauri://drag-drop", ...)` 直接收 paths。计划文件清单第 69 行 `window/manager.rs MODIFY` 项**未做**（更优）。
4. `FilePayload` 增 `Serialize`（命令返回需序列化）；新增 `base64 = "0.22"` 依赖 + `use base64::Engine`（0.22 需 trait 引入）。
