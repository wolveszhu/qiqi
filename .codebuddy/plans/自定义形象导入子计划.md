# 自定义形象导入子计划（Phase 3 · CustomSpriteRenderer）

> 落地结果文档。基于现有 `IPetRenderer` / `PetRendererBase` / `factory` 注册表，新增「导入自定义形象」能力，把单张透明 PNG 变成可上桌的桌宠形象，与内置猫狗并列管理。

## 决策（已与用户确认）

1. **动画程度**：静态图 + 形变生命感。复用呼吸缩放 / 点击果冻 / 边缘吸附躺倒（整体变换），**不含**眨眼 / 视线跟随 / 摆尾（依赖矢量分层，单图不具备）。
2. **管理范围**：多形象图库。可导入多个、重命名、删除、设为当前，与猫狗在选项卡并列。
3. **贴合微调**：导入后提供缩放滑杆 + 锚点 X/Y 滑杆，把美术图「圆盘中心」对齐物理旋转中心，实时预览并更新命中区与边缘吸附圆心。

## 架构要点

- **渲染器不复用 `PetRendererBase`**：基类 `draw()` 强约束矢量 `PetLayers`，故 `CustomSpriteRenderer` 独立实现 `IPetRenderer`，仅复用 `physics.ts` 纯函数（breathScales / dampedRecovery / jellyImpulse）与等价 Ticker + 边缘吸附旋转数学（参数化几何来自 `CustomAvatarConfig`）。
- **图片进入 WebView**：Rust 命令 `read_custom_avatar` 读文件 → base64 DataURL → 前端 `PIXI Assets.load(dataURL)` 建纹理；`customAvatarRegistry` 内存缓存避免重复 IPC。
- **前端零文件系统访问**：`tauri-plugin-dialog` 仅取路径字符串，读取 / 拷贝 / 落库全部在 Rust 命令内（`std::fs` + SQLCipher），契合 baseline §G。
- **动态 id**：`active_renderer` 直接存 `custom:<uuid>`；`factory.createRenderer` 对 `custom:` 前缀查注册表构造 `CustomSpriteRenderer`。切换沿用既有 `pet:renderer:changed` + `rebuildRenderer` 链路，不新增跨层通道。

## 使用流程

1. 窗口 B「选择形象」点虚线「＋导入自定义形象」→ 系统对话框选单张透明 PNG。
2. Rust 校验（PNG 签名 + ≤10MB）→ 拷入 `app_data_dir/custom_avatars/<uuid>/avatar.png` → 落库。
3. 注册表即时插入，形象设为当前，自动展开「自定义形象微调」面板。
4. 拖锚点 X/Y 让躺倒时露出期望部位；缩放回整体大小；改名 / 删除即时生效。
5. 窗口 A 与预览舞台当场用导入图渲染：呼吸起伏、点击 Q 弹、拖到屏边躺倒只露半圆。

## 备注

- 前端单测：项目当前未配置 Vitest 等测试运行器（见 CODEBUDDY.md），本计划未新增前端单测；数据层由 Rust 单测覆盖。后续若引入 Vitest，可补 `customAvatarRegistry` 的 `uuidFromFullId` / `listCustomAvatarIds` 与 `CustomSpriteRenderer` 的 `getHitRegion` / 边缘吸附断言。
- 边缘吸附躺倒的旋转中心即「锚点（归一化）映射到图片的圆盘中心」，默认 (0.5,0.5)=图片中心；非正方形 / 偏心美术图需在微调面板校正。
- 删除「当前使用中」形象时，Rust 自动回退 `active_renderer` 为 `code_cat` 并 emit `pet:renderer:changed`，避免孤儿引用。
